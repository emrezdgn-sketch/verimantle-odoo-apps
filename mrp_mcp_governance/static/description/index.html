AI agents propose. People decide.

Assistants are starting to create orders and move stock inside Odoo. This module answers the question that follows: who approved that — by making sure the agent never wrote it in the first place.

Not write-then-undo. Never wrote.

Tools that record what an agent changed, and offer to roll it back, assume rollback is a remedy. Once a lot has shipped, it is not.

Here a sensitive action produces a proposal. The agent has no write rights on any business model, so the proposal is the most it can do. A person turns it into a real document, under their own access rights.

Step 1 Agent asks

A tool validates the request and creates a proposal. It carries a plain-language summary written from validated data, not free text from the model.

Step 2 Nothing happens yet

No manufacturing order, no stock move, no product. Only a proposal row waiting for review.

Step 3 A person decides

Approve and it becomes a real document, created under the reviewer's own rights. Reject and it stays a record of what was asked.

What stops this from being decoration

RuleWhy it is there
Separation of duties Whoever a proposal was requested for cannot approve it, and the agent identity can never approve anything. Without this, an agent running inside someone's session would request and approve in one breath and no human would appear in the loop.
Applied as the reviewer There is no sudo() in the apply path. A reviewer who may not create a manufacturing order by hand does not create one by approving either.
Validated on arrival An archived bill of materials, a zero quantity, a missing warehouse: refused when the proposal is made. A reviewer is never shown something that would fail on approval.
Proposals expire Stock moves. A four-hour-old “this is buildable” is not a fact any more, so an unreviewed proposal goes stale rather than becoming a stale order.

An audit log that records what was read

Every tool call is logged, including read-only ones, in an append-only table: tool, arguments, duration, outcome, which session, on whose behalf.

Products that log only writes cannot answer the question an auditor actually asks — what did the agent look at before it suggested that? A proposal is only as defensible as the evidence behind it.

What you get

  • Proposal records for manufacturing orders, with hooks for sales, purchase, inventory adjustments and product revisions.
  • An approval queue with approve, reject with reason, and apply as separate auditable events.
  • An append-only tool-call log covering reads as well as writes.
  • Group and record rules that keep one agent's proposals invisible to another.
  • Extension points: add a proposal type by supplying a validator and an applier; the dispatch code does not change.
