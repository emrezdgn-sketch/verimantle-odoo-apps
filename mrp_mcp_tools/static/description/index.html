Ask your assistant what you can actually build today

Eight read-only tools that let Claude, ChatGPT or Gemini answer real questions about stock, lots, bills of materials and shortages — served by Odoo itself, over the Model Context Protocol. Nothing here writes a record.

The answer most connectors get wrong

You have twenty plates on the shelf. Ten brackets need twenty plates. So the answer is yes — except six of those plates are already reserved for another order.

Built so the answers stay honest

Free stock, not shelf stock

Every quantity excludes what is already committed to other work. It reflects what can start today.

Every answer states its blind spots

Incoming orders, work-center capacity and lot constraints are not counted — and each answer says so, so a snapshot is not relayed as a promise.

Questions, not raw records

Tools shaped around what a factory asks, instead of generic record access that leaves the model guessing at your schema.

It cannot write. That is enforced, not promised.

The agent connects as a dedicated Odoo user holding read rights on thirteen models and nothing else — no create, no write, no delete on any business model. It is never given the manufacturing or inventory user groups, because those carry write and create.

So the guarantee does not rest on this module behaving well. Point any protocol at that API key — XML-RPC, JSON-RPC, the web client — and Odoo’s own access control refuses the write:

Reads   bills of materials, stock, manufacturing orders   allowed
Writes  create order / change stock / edit BOM / delete   refused (5/5)

That proof ships with the module as a script you can run against your own deployment. It attempts those five writes over real RPC and exits non-zero if any of them is ever permitted, so the guarantee is checked on every deployment rather than trusted once.

Where the guarantee comes from, precisely. Two things, and it is worth being exact about which is which. Odoo’s access control denies create, write and delete to the agent — that is the platform, and it holds against any protocol. Keeping the module’s own code from escalating past it with sudo() is a rule rather than a sandbox: a static check scans the tool and endpoint source on every test run and fails the build if a privilege-escalating or writing call appears. Neither protects against someone with database or server access, who bypasses Odoo entirely.

Setting it up

The endpoint is served by Odoo. There is no companion process to install, no separate service to keep running.

  • Install the module.
  • Create the agent user and generate an Odoo API key for it.
  • Point your assistant at /mcp with that key as a bearer token.

Approvals and audit. This module reads. When you want an assistant to be able to suggest work — a manufacturing order, a purchase — without ever writing it, add MCP Agent Governance: proposals instead of writes, an approval queue with separation of duties, and an append-only log of every tool call including reads.

Scope. Manufacturing, inventory and bills of materials. It does not cover quality inspection, non-conformance, first-article inspection or document control — Odoo Community has no models for those, and this module does not pretend otherwise.

Requirements

  • Odoo 19.0, Community or Enterprise
  • The mrp and stock modules
  • An MCP-capable assistant
